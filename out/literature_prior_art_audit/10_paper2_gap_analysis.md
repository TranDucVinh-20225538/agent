# Paper 2 gap analysis

Written after, and conditioned on, the full novelty audit above — not before it. Cross-referenced against `paper/paper2_counterfactual_eval/DESIGN.md` (the existing Phase-1 measurement-object note, reviewed in Round 31 of `claude/decision-objects-audit-2026-08.md`).

## What already exists and Paper 2 should not rebuild

- **Judge-accuracy-vs-human-label auditing** is a saturated sub-literature: AgentRewardBench (arXiv:2504.08942, 1,302 expert-annotated trajectories, 5 benchmarks, 4 LLM judges), RuVerBench (arXiv:2606.29920, rubric-judge noise at scale), Norman et al.'s large-scale judge reliability study (arXiv:2606.19544, 21 judges, ~541K judgments), GroundEval (arXiv:2606.22737, deterministic evidence-contract replacement for LLM judges). Paper 2's contribution should not be "yet another judge-accuracy audit" — that ground is well covered and Paper 2's DESIGN.md already avoids it by design (anti-goal #5: "Do not use an LLM to decide M_i").
- **Retrospective trajectory auditing for false/corrupt success** is likewise well covered (Advani arXiv:2606.09863, Cao et al. arXiv:2603.03116, Dong et al. arXiv:2607.28367, Gao & Zhou arXiv:2605.10448). Paper 2 should not re-derive a new post-hoc auditing method for existing benchmark runs; its distinguishing move is a forward, controlled, paired-intervention protocol, which none of these use.
- **A bespoke, judge-computed sensitivity score that conflates tracking-correctness and score-computation into one number** — this is what Turk's CSS does (an LLM judge scores {0, 0.5, 1.0} whether the recommendation updated correctly; that score IS both the tracking measurement and the metric). Paper 2's DESIGN.md already avoids this by design: §3.1 explicitly bans LLM-as-judge for the match indicator M_i, and §1's table explicitly separates "gold D" (guest probes) from "S(τ)=J(τ)" (rubric score) as never-substitutable inputs. This is the correct differentiation from the closest prior art and should be kept, not weakened.
- **Rubric/policy-perturbation sensitivity testing for judges** (Weng, Feng & Xie, arXiv:2605.06161, "Policy Invariance") is the closest existing methodology to "perturb something and check whether a judge's verdict responds appropriately" — but it perturbs the judge's own policy text, not environment state, and has no agent under evaluation. Worth a citation as adjacent methodology, not a template to follow (Paper 2's object is agent+environment+judge together, not judge-in-isolation).

## What appears to be a genuine, checkable gap — safe to build on

- **A three-way (not two-way) separable-construct taxonomy** applied via a paired environment-state intervention, for computer-use agents, using an existing third-party benchmark's own black-box score as the object under test (not a bespoke replacement metric) — not found anywhere in this search. This is Paper 2's strongest claim to originality and matches DESIGN.md's own framing (§4's Alignment 2×2, explicitly built as "the existing taxonomy... not a rebrand").
- **A typed, weighted, partial-credit tracking score (STS) with an explicit gold-matching protocol keyed to component `kind`** (money_usd / integer / categorical / entity / state) — no analogue found. Turk's CSS is a single whole-case {0, 0.5, 1.0} judgment, not a weighted sum over typed sub-components; AcquaBench's GOLD/SHAM is a binary per-query outcome, not a partial-credit score. DESIGN.md's §3.2 match-by-kind table (with the `state` kind specifically built for joint/relational components like the OddsMarket case) appears to be genuinely new relative to everything found in this search.
- **A registry-leakage discipline treating the determining-set registry itself as an attack surface** (DESIGN.md §3.3: the registry must not be agent-readable, guest gold from a probe the agent never runs, writer track fields excluded) — no equivalent discipline was found articulated this explicitly in any paper searched. Worth keeping and, if space allows, worth stating as a design principle in Paper 2's own text since it doesn't appear to be a solved problem elsewhere.

## What Paper 2 should NOT do, given what this audit found

- **Do not claim to be the first to show a score can be blind to a real state change.** Turk (2605.30590) already shows this, off-domain, and should be cited as establishing the general phenomenon; Paper 2's claim should be the CUA-domain instantiation plus the three-way taxonomy plus the typed partial-credit metric, not the general insight.
- **Do not commit, in this phase, to full cross-harness/cross-agent-family generality as a required deliverable.** This audit found no existing paper or benchmark that has built a portable spec + multi-harness executed validation for this kind of protocol — meaning it is open territory, but also meaning there is no existing template to lean on, which raises the execution cost of doing it well. This reinforces (does not overturn) the Round 30/31 recommendation already on record: scope the first executed validation to the already-proven MyPCBench substrate, keep the spec portable on paper, and treat cross-harness execution as explicit future work.
- **Do not adopt "false success" or "corrupt success" as Paper 2's headline term** without qualification — both are taken by specific, differently-defined papers (Advani; Cao et al.) that use retrospective auditing, not paired intervention; reusing either term without clear differentiation risks a reviewer assuming methodological overlap that isn't there.

## One open question this audit surfaces for Paper 2's design, not yet resolved

Turk's CSS/CMS comparison is explicitly flagged in the paper itself as statistically underpowered (Spearman ρ=−0.49, exact permutation p=0.36 at n=6). If Paper 2's eventual larger-registry validation phase produces a similarly small n per model (as Paper 1's own audit did — n≤9 per primary model), the same underpowered-correlation problem will recur when comparing STS/Alignment-cell distributions across models. Worth flagging now, before Phase 3 registry sizing, that Paper 2's own DESIGN.md §5 anti-goal #3 ("do not take '30-50 tasks' as a success criterion... sized by coverage of kind/intervention operators, not CI width") correctly avoids optimizing for statistical power, but the eventual paper will still need to report this limitation honestly the way Turk's own paper does, rather than let a small-n correlation stand unqualified.
