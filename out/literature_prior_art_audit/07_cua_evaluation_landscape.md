## Reading across the landscape

Every CUA/web-agent benchmark surveyed grades a **single execution** against a fixed ground truth (a DB row, a file, a page state, a rubric). None of them, as part of their own published protocol, run the same task twice under a controlled before/after state intervention and separately report whether (a) the agent's answer tracks the new state and (b) the benchmark's own score is sensitive to that same change. The two benchmarks with the most relevant self-awareness are OSWorld (its own §7 explicitly flags that completion scores don't capture everything, and it has a separate UI-perturbation robustness study) and AppWorld (unit tests that check for unintended collateral state changes, showing design-level awareness that "did the state end up right" is a richer question than pass/fail). Neither performs Paper 1's paired determining-set intervention. This is consistent with the finding in `08_direct_prior_art.md` that the closest CUA-domain paper (Dong et al., 2607.28367) approaches the same concern from a retrospective-audit angle rather than a controlled-intervention one.
